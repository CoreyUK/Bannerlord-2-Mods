Strategic Campaign AI - v0.2.0 (for Bannerlord v1.4.8)
======================================================

A repair release. The short version: most of what this mod advertised was never
actually running, and the part that did run was telling the AI that no enemy
settlement was ever worth attacking. That is the cause of essentially every
report on this page - armies circling their own fiefs, sitting in towns until
they disband, defending instead of besieging, and the frame rate drops.

REQUIRES BANNERLORD v1.4.8. Do not use on 1.4.5 or 1.4.7.


THE MAIN FIX
------------
Target scoring penalties compounded without any limit. In the worst case an
enemy settlement ended up scoring under 1/2000 of its normal value while a
friendly settlement was worth around 20x extra to defend. The AI concluded,
correctly given those numbers, that attacking was never worth it and guarding
always was.

Separately, war strength was being counted against every faction a kingdom was
at war with - which includes the minor factions and bandit clans that everyone
is permanently at war with. Every kingdom was therefore measured against 9-12
"enemies" whose combined strength dwarfed any single realm, so every kingdom was
permanently flagged as war-exhausted and locked onto a peace-seeking posture
from the opening day of a campaign.

Both are fixed. Preferences are now combined into a single clamped multiplier,
and only kingdom-versus-kingdom wars count toward strength and threat.

In testing, kingdoms now diverge into distinct war goals, contest border fiefs,
and take them off each other in both directions.


A NOTE ON DIRECT ARMY ORDERS
----------------------------
The army role layer (aggression, defence, interception, reserve) and everything
under it - objectives, staging, raid response, stuck-army recovery - was present
in the code but never called. No move order was ever issued.

It has been repaired and is available, but it now ships DISABLED, on evidence:

- It fights the vanilla AI. Vanilla re-plans on its own schedule and clears the
  mod's move orders, so the mod re-imposes them. One lord was re-sent to the same
  castle six times over three days and never arrived. That tug of war is the
  "armies running in circles" report, and the order layer was reproducing it.

- It produced worse results. Across comparable runs the corrected scoring on its
  own achieved roughly three times as many successful sieges as it did with the
  order layer active. Vanilla executes the mod's scoring perfectly well once the
  scores are right; interrupting its armies only gets in the way.

Set EnableStrategicOrders = true in ModuleData/settings.txt if you want it.


THE CRASH
---------
Earlier builds could hard-crash the game roughly 15-21 in-game days into a
campaign. It was traced by elimination over six test runs: unmodded Bannerlord
ran clean past the failure point, and so did this mod with garrison
reinforcement disabled, while every single crash occurred with it enabled.

That feature moved troops into a weak garrison by mutating party rosters
directly, because the campaign system provides no action for transferring troops
to a garrison. It is now OFF by default. It is also the feature behind the older
"troops disappear when entering a city" report.

Direct army orders are off by default as well (see above), which removes the
other subsystem that reached into engine state.


CRASHES, SAVES AND PERFORMANCE
------------------------------
- Frame rate. Target scoring runs for every party against every candidate
  settlement, and each call walked the full settlement list five times plus every
  lord party on the map, while building throwaway strings for the weather check.
  Results are now cached per campaign hour and settlement lookups are no longer
  linear scans.

- Live map weather was being read with MapWeatherModel.UpdateWeatherForPosition,
  an engine method that mutates cached weather state, called a few thousand times
  an hour from the scoring path. It now uses the read-only getter, and the
  weather modifier is off by default. Season effects are unaffected.

- Siege retreat used reflection to call a private engine method, and re-fired on
  the same siege every four hours when the lift did not take effect - eight times
  on a single siege in testing. Now limited to one attempt per settlement, and
  off by default.

- NullReferenceException in StrategicTargetScoreModel.GetTargetScoreForFaction.
  Only the vanilla call was guarded. Faction access is now null-safe throughout
  and both scoring overrides fall back to the unmodified vanilla score rather
  than throwing inside the AI decision loop.

- Strategic memory now survives saving and loading. The original save failure was
  caused by writing dictionaries the save system had not been told about; it
  needed a save definer, which is now present. Siege failures, lord cooldowns,
  army objectives, war goals and lost-fief claims persist, and expired entries
  are pruned daily so saves do not grow. Older saves still load.

- Strategic memory used to leak between campaigns played in the same session, so
  a new game could inherit the previous one's cooldowns and war goals.


OTHER FIXES
-----------
- Armies were disbanded from inside the army-created event, so the kingdom AI
  re-formed them on the next tick and lords churned instead of campaigning.
  Gating now happens up front when an army is proposed.
- Neighbouring territory owned by neutral kingdoms was treated as friendly
  ground, so unrelated enemy towns scored as reachable frontline targets.
- A fief counted as "threatened" merely for being near a border, which fed the
  exhaustion test. It now needs enemy strength meaningfully above the garrison.
- The player is excluded more thoroughly: player-led armies and player-owned
  fiefs are never touched by garrison donations or strategic orders.


ADDED
-----
- ModuleData/settings.txt - around 45 documented settings, no rebuild needed,
  applied on restart. If the AI still looks too passive, raise
  MinOffenseMultiplier and lower MaxDefenseMultiplier.
- A diagnostic log at Documents\Mount and Blade II Bannerlord\StrategicCampaignAI.log.
  Set VerboseLogging = true before reporting a problem and attach it.


CHANGED
-------
- Updated to Bannerlord v1.4.8.
- The older StrategicCampaignAI module is marked incompatible. Both register the
  same campaign models, so running them together double-applies every modifier.
- Removed a stale unused DLL that was being shipped inside the download.


UPGRADING
---------
Safe to add or remove mid-save. Delete the old module folder before installing.
